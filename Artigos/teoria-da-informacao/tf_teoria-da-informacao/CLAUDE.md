## What this repository is

Academic final project (TF) for **Teoria da Informação (TIP7266, PPGETI/UFC, 2026.1)**. It is not a software product — it is a **reproducible research paper**: a Python analysis pipeline that computes information-theoretic scalars from on-chip aging-sensor logs, plus a LaTeX document that consumes those scalars. There is no application to "run" in the conventional sense; the graded deliverable is `latex/main_pt.pdf` (Portuguese — the course's rubric grades Portuguese prose). `latex/main.tex`/`main.pdf` is an English variant kept for potential future publication; as of 2026-08-19 it has **not** been ported through four rounds of independent-review fixes applied to `main_pt.tex` (see `review/prompt_correcoes_TF.md`, `review/prompt_correcoes_finais_TF.md`, `review/prompt_correcoes_rodada4_TF.md`) and should not be treated as current. `latex/seminar.tex`/`seminar.pdf` is the full, canonical Portuguese deck (includes the KL/JS bench-fidelity and ICA slides, the caveats slide and backups). `latex/seminar_15min.tex` is the 10-slide cut actually presented at the 2026-08-22 defense, and `latex/entregue_2026-08-22/trabalho_final.pdf` is the paper as submitted that day (a trimmed version without the KL/JS and ICA sections). The sources in `sections_pt/` are the fuller version: they keep those sections because they feed the IEEE D&T extension of the GSEM burn-in thermal-control article (`../../Artigos_GSEM/`). Do not re-trim them.

The science: treat an on-chip slack sensor as a noisy communication channel (latent aging = transmitter; reversible PVT + quantization = noise; RUL estimator = receiver) and re-express noise, PVT correction, and aging recoverability in entropy / mutual information / divergence / capacity / estimation terms. The headline contribution is replacing the prior linear $R^2$ with **mutual information in bits**. Full context lives in `00_Work_Summary.md` (read this first) and the numbered planning docs `01`–`05`.

## Build and run

Two stages — **always run the analysis before building the paper**, because the paper's numbers and figures are generated by the analysis.

The `Makefile` wraps both stages: `make` (creates `.venv` from `analysis/requirements.txt`, runs the five scripts in order, builds `main_pt`/`seminar`/`seminar_15min`/`main`), or `make analysis` / `make pdf` / `make clean` individually. Manual equivalent:

```bash
# 1. Analysis (from analysis/) — needs numpy, scipy, matplotlib; no sklearn
cd analysis
python3 tier1_pipeline.py        # entropy, MI, surrogate floor, PVT correction, capacity, BSC, CRLB + Bayesian RUL
python3 kl_benches.py            # KL / JS divergence between the two benches (device B)
python3 ica_separation.py        # FastICA blind source separation (device A)
python3 kalman_rul.py            # Wiener/Kalman denoised aging trajectory + Inverse-Gaussian RUL distribution
python3 make_figures.py          # writes the 6 PDF figures into ../latex/figures/ (imports from all of the above)

# Run tier1 on a different log:
python3 tier1_pipeline.py path/to/another_log.csv

# 2. Paper (from latex/)
cd latex
latexmk -pdf main.tex            # preferred; or: pdflatex main && bibtex main && pdflatex main && pdflatex main
```

`tier1_pipeline.py` runs in ~4 s on the 768 k-sample log. There is no test suite, linter, or CI — the project's correctness check is the surrogate null floor and the frequentist/Bayesian cross-checks inside the pipeline itself.

## The reproducibility contract (most important architectural rule)

**Numbers and figures are NEVER typed into the LaTeX prose.** The data flows one way:

```
CSV logs (artigos/)
   → analysis/*.py
       → analysis/results.json                 (machine-readable scalars)
       → latex/generated/values.tex            (every scalar as a \newcommand macro)
       → latex/figures/*.pdf                    (the 5 figures)
   → latex/sections/*.tex reference scalars via macros (\valHs, \valRsqLinear, …)
```

Consequences when editing:
- To change a number in the paper, change the computation in the relevant `analysis/*.py`, then re-run it — do **not** hand-edit `values.tex` or `results.json` (they are regenerated and overwritten). Each of `tier1_pipeline.py`, `kl_benches.py`, `ica_separation.py` and `kalman_rul.py` has its own `write_values_tex` (near the bottom of each file) that fills only its own macros in place, leaving the rest of `values.tex` untouched — this is why the analysis scripts must all be re-run, in the order given above, after any change to the source CSVs. As of 2026-08, every macro in `values.tex` is emitted by one of these four scripts; none are hand-typed (previously `\valHs`, `\valRsqLinear` and the dataset descriptive stats were hand-typed literals — this was a real bug, fixed by computing them in `tier1_pipeline.py`'s `main()`, including R² from the same OLS fit used for the PVT correction rather than a hardcoded `0.738`).
- Prose in `sections/*.tex` must cite a macro, not a literal. If a needed macro doesn't exist yet, add it to the pipeline's emitter, not inline.
- `[TODO]` in `values.tex` / `tables/*.tex` marks a scalar the pipeline hasn't filled yet.

## Pipeline structure

`tier1_pipeline.py` is one ordered `main()` mirroring the paper's 5-stage arc (acquire → transform → quantify → preserve → infer). Stage helpers above `main()` are pure functions; key invariants:

- **`n_eff`, not `n`, governs every confidence statement.** The 1 Hz series is heavily autocorrelated (`tau_int ≈ 314 samples`), so `n_eff = n / (2·tau_int) ≈ 1,224` despite 768,884 raw samples. Block-bootstrap CIs and the surrogate null floor all use `n_eff`. Preserve this when adding any inference — never use the raw count for variance/CI.
- **Residual MI must be measured on *detrended* signals.** After PVT correction the exposed aging drift inflates apparent residual coupling; the same trend confound makes raw ICA inter-component MI meaningless (~8 bits artifact). Detrend before any post-correction MI.
- MI is estimated two ways (binned + Miller–Madow, and KSG/Kraskov) and cross-checked; RUL is computed both frequentist (CRLB) and Bayesian (Student-t posterior) and they must agree.

`make_figures.py` reads the same CSVs and emits `fig_correction`, `fig_mi`, `fig_kl`, `fig_ica`, `fig_capacity_rul` as PDFs into `latex/figures/`.

## Data — never mix the two devices

- **Device A** = `artigos/Tentative_1_20260524_203756.csv` (214.6 h PID aging campaign). Source for ALL entropy / MI / PVT-correction / capacity / BSC / RUL / ICA / Wiener-Kalman results.
- **Device B** = `artigos/TCC vs SBCCI/*.csv` (two ~24 h benches, SBCCI vs PID). Used **only** by `kl_benches.py` for bench-fidelity KL/JS comparison.

Device A and Device B results must stay separate in both code and prose — the KL comparison speaks to bench/environment fidelity, not aging, and conflating them is a correctness error the project explicitly guards against. The pipeline drops link-down dropouts and the first 1 h soak before analysis (`clean()` / load).

## LaTeX layout

`main.tex` is the master; `\input` order is document order. `notation.tex` is the single source of truth for symbols. Default `\documentclass` is `article` for portability; switching to IEEE is a one-line change documented at the top of `main.tex`. Sections map to the planning docs (see `latex/README.md` for the section→doc mapping).

## Scope decisions (do not "complete" these — they are deliberate omissions)

Out of scope by explicit decision, because they correlate weakly with the research or are redundant with results already computed: concrete source-coding codecs (Huffman/LZW), channel error-correcting codes, and Big Data/streaming tooling (MapReduce/Spark). The honesty caveats carried in the paper (single aging device; `n_eff ≪ n`; capacity as effective-resolution heuristic; ICA corroborative not a clean unmixing) are intentional framing, not gaps to patch.
